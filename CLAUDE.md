# Путь проводника — задание на MVP

Этот файл — входная точка для Claude Code. Прочитай его целиком, затем файлы из раздела 2 в указанном порядке. Только после этого начинай работу с этапа 0.

## 1. Что строим и зачем

Квест-приложение для одного человека — Дениса. Это эксперимент: работает ли геймификация в реальной работе. Работа — направление «рост бизнесов»: подготовка, разговоры с собственниками, первые клиенты.

- Квесты висят на доске заказов. Их берут в журнал (2 слота), отмечают задачи и сдают с заметкой.
- **XP — это опыт, а не счётчик работы.** Его дают задачи вида «изучение», «тренировка», «бой» (реальный разговор с людьми). Уровень открывает сложные квесты. С уровня 4 повышение требует испытания: сданной тренировки или боя.
- **Золото — за работу.** Тратится в казне на мелкие плюшки.
- **Сундуки** — реальные вещи из списка желаний. Выпадают случайно в конце сложной цепочки квестов.
- **Главная метрика эксперимента:** растут ли внешние события (бои), а не только галочки.

Готовый результат — сайт на Vercel. На нём Денис играет главу 1 каждый день, и прогресс хранится в базе.

## 3. Незыблемые правила

1. **Логика живёт только в `engine/src/engine.ts`.** Сайт, API и скрипты вызывают движок и ничего не пересчитывают сами. Нашёл расчёт вне движка — перенеси его в движок.
2. **Числа — только в `content/rules.json`.** В коде нет ставок, порогов и курсов.
3. **У каждого вида данных один дом.**
   - Контент живёт в репо, квесты на сайте не создаются.
   - Действия — в таблице `events`, только дописываются, никогда не правятся и не удаляются.
   - Уровень, XP, золото и статусы нигде не хранятся, их всегда считает `derive`.
4. **Любое действие проверяет сервер через `canApply`** до записи события. Клиент не присылает суммы и выпавшие вещи: золото за обмен и за покупку и вещь из сундука вычисляет сервер.
5. **Изменение поведения движка — только вместе с тестом или JSON-сценарием** в `engine/test/scenarios/`. Перед каждым коммитом `npm test` и `npm run check` должны быть зелёными.
6. **Тексты интерфейса — на русском, как в прототипе.** Кнопки: «Снять заказ», «Сдать квест», «Отложить», «Вернуть в работу», «Открыть сундук», «Получил», «Купить».
7. **Правила игры меняет только Денис.** Если кажется, что правило надо поменять (ставки, испытание, сундуки), не меняй сам: опиши предложение и спроси.
8. **В MVP не входят** навыки, перки, редкость артефактов, характеристики этапа, сезоны и мана. Не добавляй их.

## 4. Стек и архитектура

- **Next.js** (App Router) + TypeScript, деплой на **Vercel**.
- **Supabase**: Postgres и вход для одного пользователя по magic link на почту Дениса.
- **Движок** импортируется как модуль: `engine/src/engine.ts`. Контент — JSON из `content/`, читается при сборке, никакой CMS.
- **Стили:** глобально подключить `design/tokens.css` и `design/components.css`, классы — как в прототипе. CSS-фреймворк не нужен.

### База

```sql
create table events (
  id uuid primary key default gen_random_uuid(),
  user_id uuid not null references auth.users(id),
  at timestamptz not null default now(),
  type text not null,              -- quest_taken | quest_dropped | task_set | quest_submitted | quest_reopened
                                   -- chest_opened | chest_received | chest_swapped | shop_bought
  payload jsonb not null           -- поля события GameEvent без t и at
);
create index on events (user_id, at);
alter table events enable row level security;
create policy "own events" on events for all using (user_id = auth.uid()) with check (user_id = auth.uid());

create table notes (                -- заметки по прототипу, не игровая логика
  user_id uuid primary key references auth.users(id),
  text text not null default '',
  updated_at timestamptz not null default now()
);
```

Для таблицы `events` разрешены только `insert` и `select`, `update` и `delete` запрещены.

### API

| Маршрут | Что делает |
|---|---|
| `GET /api/state` | читает события пользователя по `at`, возвращает `derive(events, content)` |
| `POST /api/events` | принимает намерение, сервер дополняет его (ниже), `canApply` → 400 с текстом ошибки или запись и новое состояние |
| `GET /api/export` | журнал событий JSON: `{ version, exported, events, notes }`, как кнопка в прототипе |
| `PUT /api/notes` | сохранить заметки |

Что сервер дописывает в событие сам:
- `chest_opened` — выбирает вещь случайно и равновероятно среди `state.pool` нужного тира;
- `chest_swapped` — `gold = swapValue(item, rules)`;
- `shop_bought` — `gold` из `rewards/shop.json`.

Клиент эти поля не присылает.

**Первый вход:** если событий нет, сервер записывает стартовые события из `content/seed.json`: 1.1 и 1.2 сданы, слоты свободны.

### Интерфейс

- Маршруты: `/board` (по умолчанию), `/map`, `/hero`. Окно квеста — модальное по `?q=<id>`, окно сундука — по `?chest=<chainId>`.
- Компоненты — по таблице в `docs/handoff.md`. Разметка и классы перенесены из `proto/template.html`: Шапка, Заказ, Печать, Разыскивается, Журнал и Слот, Окно квеста с формой сдачи, Метка карты, Сундук, Страж, Баннер, Панель героя, Казна, Летопись, «До уровня N», Тост.
- Клиент получает состояние с сервера. Для мгновенного отклика он может сам вызвать `derive` и `canApply` на тех же событиях, но истина — ответ сервера.
- Адаптив как в прототипе: доска `auto-fill minmax(220px, 1fr)`, карта прокручивается вбок внутри блока, окно квеста на телефоне во всю ширину.

## 5. Этапы

Каждый этап — отдельный пулл-реквест или серия коммитов. Перед каждым коммитом зелёные `npm test` и `npm run check`.

### Этап 0 · Подготовка репо
- Дать задачам постоянные `id` вида `"П.1-a"`.
  - Добавить `id` в `Task`.
  - `task_set` хранит `task` (id), а не номер. В `QuestState.tasks` использовать словарь по id.
  - `validate` проверяет, что id задач уникальны.
  - Обновить тесты, сценарии и прототип.
- Добавить в `validate` предупреждение «часы у задачи изменились после взятия». Пока оно работает как заготовка без базы, полная проверка появится на этапе 2.
- **Готово, когда** все тесты и `check` зелёные, а прототип собирается и работает как раньше.

### Этап 1 · Интерфейс на Next.js без базы
- Каркас Next.js, движок и контент подключены.
- Временное хранилище событий — `localStorage`, как в прототипе.
- Все экраны и состояния из `docs/handoff.md` перенесены один в один.
- **Готово, когда** прохождение всей главы 1 в браузере даёт те же числа, что `npm run check` (1120 XP, уровень 5, 185 золота), и все плашки выглядят как в прототипе.

### Этап 2 · Supabase и API
- Таблицы и политики из раздела 4, вход по magic link, маршруты API, серверная проверка `canApply`, серверный выбор вещи из сундука, стартовые события.
- **Готово, когда:**
  - запрос в обход интерфейса — например, сдать квест без отмеченных задач или взять третий квест — получает 400;
  - после перезагрузки и с другого устройства прогресс тот же.

### Этап 3 · Выкатка и автоматическая проверка
- Vercel.
- GitHub Actions на каждый push: `npm test`, `npm run check`, сборка. Ошибка в контенте не даёт выкатить.
- **Готово, когда** правка `content/zones/zone-1.json` сама приводит к новой выкатке, а битый контент блокирует её.

### Этап 4 · Обратная связь
- Во вкладке «Персонаж»: заметки (`/api/notes`), «Скопировать статус для Claude», «Скопировать журнал событий (JSON)» и «Скачать JSON» через `/api/export`.
- **Готово, когда** выгрузка из MVP читается тем же `derive` и даёт то же состояние.

## 6. Решения, которые ещё за Денисом (по умолчанию — как сейчас)

| Вопрос | Сейчас | Где меняется |
|---|---|---|
| Стиль | «Путь проводника»: ночь, пергамент, золото | `design/tokens.css` и часть `components.css` |
| Курс золота | 170 ₸ за 1 золото, заглушка | `rules.json → rate_kzt_per_gold` |
| Доля цены при обмене вещи из сундука | 1.0, полная цена. Даёт около 600 золота при 155 за главу, есть дисбаланс | `rules.json → swap_share` |
| Пул сундука и витрина казны | заглушки | `content/rewards/*.json` |
| Бюджет казны и фонд сундуков | не заданы | после решения — в `rules.json` |

Не блокируйся на них: делай по текущим значениям и держи их только в `rules.json`.
