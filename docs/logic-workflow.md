# Как менять логику быстро

Вся логика живёт в одном файле `engine/src/engine.ts`. Один и тот же код работает в прототипе, на бэкенде (API Next.js) и в отчётах. Второй копии логики нет нигде — ни на сайте, ни в скриптах.

## Три уровня правки

| Что меняем | Где | Код нужен? | Проверка | Сколько времени |
|---|---|---|---|---|
| **Числа**: ставка XP за час, золото, округление, слоты, бонус цепочки, с какого уровня испытание, курс, доля при обмене, тиры | `content/rules.json` | нет | `npm run check` | минуты |
| **Контент**: квесты, задачи, вид и часы, зависимости, допуск, цепочки, ключи босса, место на карте | `content/zones/zone-N.json` | нет | `npm run check` | минуты |
| **Механика**: новая формула, навыки, перки, редкость, новое событие | `engine/src/engine.ts` | да | `npm test`, затем `npm run check` | час и больше |

90% правок — первые два уровня, это данные, а не код.

## Что делает `npm run check`

1. **Проверяет контент** и находит:
   - повторы ID и битые зависимости;
   - циклы;
   - квесты без названия, без «что сделать» или без условия победы;
   - неизвестные виды задач и нулевые часы;
   - подготовку без применения;
   - основные квесты без опыта;
   - побочные квесты со сроком, которые не стали ключом босса;
   - тиры сундуков без описания и пустой пул.
2. **Проигрывает главу** от начала до конца. Ловит квесты, до которых нельзя дойти из-за допуска или испытания.
3. **Печатает отчёт.** По каждому квесту: задачи, XP, золото, допуск. Ниже — уровень после каждого квеста и итог главы.
4. **Пишет** `build/report-zone-N.json`. Из него собирается лист «Логика 7» на канвасе.

Ошибка — код выхода 1, выкатка не пройдёт. Предупреждение — выкатка пройдёт, но в отчёте оно будет видно.

## Что делает `npm test`

- **Модульные тесты движка**: награда, кривая, испытание, слоты, сундук, проверка битого контента.
- **Сценарии** в `engine/test/scenarios/*.json`. Сценарий — это список квестов или событий и ожидаемый результат: XP, уровень, золото, статусы, сундук. Новый случай описывается JSON-файлом, без кода.

```json
{
  "name": "Вернуть в работу: XP и золото квеста снимаются",
  "play": ["1.1", "1.2", "П.1"],
  "events": [{"t": "quest_reopened", "q": "П.1"}],
  "expect": {"xp": 140, "level": 2, "status.П.1": "ready", "gold": 15}
}
```

## Как это выглядит в работе с Claude

1. Ты пишешь: «П.1 слишком жирный, книга даёт больше, чем тренировка» или «подними золото за работу до 15».
2. Claude правит нужный файл и запускает `npm run check`.
3. Присылает разницу: было и стало по XP, золоту и уровню на каждом шаге, плюс новые предупреждения.
4. Ты соглашаешься → коммит → Vercel выкатывает. Прототип пересобирается командой `npm run build:proto`.

## Как бэкенд использует движок (шаг 3)

- `POST /api/events`: прочитать события пользователя → `derive` → `resolveIntent(намерение)`. Он дописывает вещь из сундука и суммы и вызывает `canApply`. При ошибке вернуть 400 с текстом. Иначе записать событие и вернуть новое состояние.
- `GET /api/state`: `derive(все события, контент)`.
- Случайный выбор вещи из сундука — на сервере: `resolveIntent` для `chest_opened` (сейчас его же вызывает сайт с `localStorage`).
- Сайт рисует только то, что вернул сервер. Для мгновенного отклика он может сам вызвать тот же `derive`.

## Команды

```
npm run check          проверка контента и отчёт по главе
npm test               тесты движка и сценарии
npm run build:proto    собрать прототип из шаблона, контента и движка
```

Нужен Node 22 или новее, зависимостей нет.
