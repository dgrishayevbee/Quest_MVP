# Передача в MVP: плашки, экраны, данные

Эталон вида — прототип «Журнал квестов Consa». Стили берутся из `design/tokens.css` и `design/components.css`, оба извлечены из прототипа один в один. Все состояния каждой плашки нарисованы на канвасе: страница «Передача в MVP», лист «Плашки и состояния». Каждая плашка рисуется по полям состояния движка `State` из `engine/src/engine.ts`. Своих расчётов у плашек нет.

## Плашки

| Плашка | Когда видна | Состояния | Данные из `State` | Действие → событие |
|---|---|---|---|---|
| **Шапка** | всегда | вкладка активна / нет | `hero.xp`, `hero.level`, `gold`, `prog.length` / `rules.slots`, доля XP до уровня | смена вкладки |

| **Печать** | `status = locked` | печать зависимостей (I–V) · печать уровня | `reasons.missing`, `reasons.needLevel` | открыть окно квеста |
| **Разыскивается** | всегда на доске | ключи собраны частично · все | `bossKeys`, `zone2.min_level` | открыть окно стража |
| **Слот журнала** | `prog` | в работе · можно сдать · свободен | задачи `qs[id].tasks`, `quest.win` | галочка → `task_set`; «Сдать квест» → окно со сдачей |
| **Окно квеста** | по клику | можно взять · в работе · можно сдать · форма сдачи · сдан · под печатью | всё о квесте, `values`, `reasons`, `hero.needTrial` | `quest_taken`, `task_set`, `quest_dropped`, `quest_submitted`, `quest_reopened` |
| **Метка на карте** | для каждого квеста | «!» можно взять · «?» в работе · «?» можно сдать · сургуч сдан · тусклая под печатью | `status`, `quest.map` | открыть окно квеста |
| **Сундук** (метка и окно) | для цепочки с сундуком | закрыт · пул пуст · готов · открыт · получен · обменян | `chains[id]`, `pool`, `rules.tiers` | `chest_opened` (выбор на сервере), `chest_received`, `chest_swapped` |
| **Страж** (метка и окно) | всегда | закрыт · пропускает | `bossKeys`, `bossOpen`, `hero.level` | — |
| **Баннер** | по условию | сундук готов · вещь выпала · пул пуст · испытание · страж пропускает | `chains`, `hero.blocked`, `bossOpen` | открыть сундук |
| **Панель героя** | вкладка «Персонаж» | трофей есть · пустой слот | `seq.length`, `tasksDone`, `battles`, `received`, `hero`, `chains.rec`, `shop` | — |

| **До уровня N** | вкладка «Персонаж» | пункт выполнен · нет | `hero`, `bossKeys`, `zone2.min_level` | — |
| **Тост** | после действия | — | текст из действия | — |

## Экраны

**Доска** (главный экран):
- слева деревянная доска: заказы → печати → «Разыскивается»;
- справа журнал со слотами и короткая справка;
- сверху баннеры.

**Карта**:
- остров зоны с метками квестов по `quest.map`;
- красный путь цепочки до сундука, страж у перевала, туман следующей главы;
- справа журнал зоны и карточка сундука.

**Персонаж**:
- панель героя: итоги слева, портрет с уровнем в центре, трофеи справа;
- ниже три блока: казна, летопись, «до уровня»;
- внизу заметки и экспорт.

**Окно квеста**: пергамент поверх любого экрана. На телефоне занимает всю ширину.

## Тексты кнопок и названия

Снять заказ · Сдать квест · Отложить · Вернуть в работу · Подробнее · Открыть сундук · Получил · Обменять на N золота · Купить · Скопировать статус для Claude · Скопировать журнал событий (JSON) · Сбросить прогресс.

Часы задач в интерфейсе не показываются: это оценка для расчёта награды, её видят только движок и `npm run check`. В «Как посчитана награда» — вид задачи и её XP и золото из `values[id].parts`.

Названия сущностей: заказ, печать, страж перевала, журнал, сундук, казна, летопись, испытание, допуск.

## Адаптив

- Доска: колонки заказов `auto-fill, minmax(220px, 1fr)`. Боковая колонка уходит вниз уже 960 px.
- Карта: фиксированный холст `zone.map.size`, на узком экране прокручивается вбок внутри своего блока.
- Персонаж: на узком экране три колонки панели и три блока снизу встают в одну.

## Графика

Вся графика — CSS и встроенный SVG, внешних картинок нет:
- щит-метка — `clip-path`;
- сургуч, сундук, ромб стража;
- компас, горы, лес, река;
- портрет.

Всё лежит в `proto/template.html` и `design/components.css`.
